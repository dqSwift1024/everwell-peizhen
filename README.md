> **让健康有人关心，让父母就医有人帮忙。**
>
> **健康来敲门（Everwell）** 是围绕**低行动能力患者（失能老年人、肢体行动障碍、术后康复人群）**及其**家庭照护责任人（子女/配偶）**打造的全链路就医陪诊与家庭日常健康关怀系统。系统严格遵循 2026 年 11 月 1 日起实施的我国首部陪诊国家标准 **《社会化陪同就医服务基本要求》（GB/T 47801—2026）**，通过数字化平台连接家庭需求端与医院现有护工机构（B端机构）及自有持证陪诊员。

## 一、 系统四端架构与职责分工

系统借鉴滴滴出行、美团外卖及头部医疗陪护平台（医伴汇、e康陪诊、金牌护士、小豚陪诊）的多端分工经验，采用 **“统一后端数据中台 + 四端差异化视图”** 架构：

| 终端名称 | 目标用户 | 核心职责与定位 |
| :--- | :--- | :--- |
| **1. Web 品牌官网端**<br>(`🖥️ Web Portal`) | 搜索访客、患者家属、拟入驻B端机构与陪诊员 | 对标 `医伴汇` + `e康陪诊`：<br>· 品牌价值主张与国标 12+7 合规公示<br>· 一至四线城市与 L0~L3 失能等级透明价格表、阶梯退改规则<br>· **免登录 10 秒快速预约通道**（提交直达管理后台待派单池）<br>· **B端陪护机构 & 个人持证陪诊师招募入驻申请**<br>· **健康文章、视频与二十四节气时令饮食专栏（SEO）** + 小程序扫码引流 |
| **2. 小程序 / App**<br>(`📱 C端家庭模式`) | 患者家属（代约决策人）、失能老人/患者本人 | 承载 **15 项 `+` 核心功能闭环**：<br>· 诊前：AI 症状梳理与医院科室导诊推荐、分级预约下单、预约挂号三路径、位置选择与一键拉起滴滴/高德打车、患者本人三选一知情授权确认<br>· 诊中/诊后：实时查看 5 步履约进度、超时加钟补差价、结果分享报告、医嘱执行每日服药打卡、合作购药入口、术后复检一键再次陪诊、保险投保入口与门诊理赔资料包一键下载<br>· 日常关怀：异地父母城市天气预警与生日/节日关怀卡片、健康日记（血压/血糖）与早晚定时平安确认 |
| **3. 小程序 / App**<br>(`🦺 陪诊师接单端`) | B端合作机构从业人员、平台自有培训人员 | 与 C 端共用同一小程序/App 工程（支持个人中心一键切换角色）：<br>· 国标数字工牌公示（实名、健康证有效期、持证名称、所属机构、3年免押金状态）<br>· **标准化 5 步现场履约打卡器**：`①确认接单` → `②到达接手位置(LBS打卡)` → `③院内陪诊进行中` → `④上传检查报告/理赔发票并结构化录入客观医嘱/用药/复检日` → `⑤送达结束交接位置完结分账` |
| **4. 管理后台端**<br>(`📊 Admin & B端机构 RBAC`) | 平台总控运营调度员、B端合作机构管理员 | 支持一键切换 **【平台总控管理员】** 与 **【B端合作机构子账号】**：<br>· **智能筛选 + 人工精准派单台**：按目标医院、患者失能等级（L0~L3）、排班空闲与持证优先自动匹配最佳陪诊员，支持一键指派与改派替补<br>· **财务与供给台账**：`≤10%` 平台撮合提成自动清分（B端机构 8%、自有人员 6%）、前 3 年免收供给端押金台账、新入驻机构/陪诊师在线审批<br>· **商业化归因看板**：体检推荐、购药、保险 6 大扩展场景点击量与广告/入口费收入实时核算 |

## 三、 核心商业与合规设计亮点

1. **全面对齐《GB/T 47801—2026》国家标准**：
   - 全流程内嵌 **“12项可为（生活与流程辅助）”** 与 **“7项禁为（不解读报告、不提供诊疗意见、不参与医疗操作、不代签法律文书）”** 红线围栏；
   - AI 导诊与诊后结果报告强制注入合规免责声明，保护平台、陪诊员与患者三方权益。
2. **双轨供给组织与轻资产盈利模型**：
   - 同时支持 **B端合作陪护机构从业人员** 与 **平台自有培训人员** 注册接单；
   - 严格落实商业计划书财务模型：**前 3 年免收供给端押金**（快速扩充医院周边护工运力池），**服务撮合提成控制在 `≤10%`**，叠加 **体检、购药、保险等扩展场景广告与入口收入**。

## 五、 数据库模型设计（11张核心表）

数据库文件位于 `data/everwell.sqlite`，由 `server/db.js` 自动初始化创建：

1. `patients`：失能老人及患者健康档案表（姓名、年龄、城市、生日、天气预警、行动能力分级 L0~L3、慢病史、授权家属名单）。
2. `organizations`：B端合作陪护机构表（机构名、统一社会信用代码、联系人、撮合提成比例 `≤10%`、3年免押金到期日、押金台账）。
3. `escorts`：陪诊师运力池表（区分 `ORG` B端机构人员与 `SELF` 自有培训人员、持证名称、健康证有效期、可承接失能等级 `L0,L1,L2,L3`、常驻医院、完单量与累计收入）。
4. `hospitals`：合作三甲医院与科室导诊库（医院名、优势科室、官方挂号渠道指引、院内共享轮椅租借位置、经纬度坐标）。
5. `orders`：陪诊核心订单表（订单号、来源终端、套餐与失能分级加价、超时补差价、挂号方式、接手与结束交接位置、患者确认状态与方式、指派陪诊师/机构、5步 SOP 打卡进度、平台提成与服务方分账金额）。
6. `medical_reports`：诊后结果分享与理赔资料表（医生原话客观医嘱、下次复检日期与准备事项、检查报告图片、门诊发票/病历/费用清单理赔资料包、患者授权查看人）。
7. `medications`：医嘱执行每日用药打卡表（药品名称、规格用法、每日频次、疗程天数、今日是否已打卡）。
8. `health_diaries`：健康日记与定时关怀表（日期、收缩压/舒张压、空腹血糖、体感状态、早晚定时关怀确认状态）。
9. `articles`：健康文章、视频与时令饮食内容表（分类、节气标签、标题、正文、关联推荐医院科室、阅读量）。
10. `commercial_slots`：商业化广告与服务入口表（体检推荐、购药入口、保险入口卡片配置、累计点击归因次数 `clicks`、单次点击结算收入）。
11. `applications`：供给端入驻申请表（B端机构或个人陪诊师在线报名记录、资质说明、后台审批状态）。

## 六、 后端 RESTful API 接口清单

| 请求方法 & 路径 | 所属模块 | 功能描述 |
| :--- | :--- | :--- |
| `GET /api/bootstrap` | 全局同步 | 获取四端全量实时业务数据与经营统计指标 |
| `POST /api/ai/triage` | AI问答与就医推荐(+) | 根据患者症状与行动能力返回就医准备清单、匹配医院科室及轮椅指引 |
| `POST /api/orders` | 预约下单(+) | 支持 Web 免登录预约与小程序/App 下单，自动核算套餐与失能分级价格及平台提成 |
| `POST /api/orders/:id/confirm-patient` | 患者确认(+) | 完成三选一患者知情授权确认（微信大字卡片 / 同机手写签名 / 现场接手补确认） |
| `POST /api/orders/:id/add-overtime` | 超时补差价 | 在线支付超时加钟补差价（¥100/小时），实时重算订单总额与分账 |
| `POST /api/orders/:id/cancel` | 阶梯退改 | 按距离服务开始时长（`>48h` / `8-48h` / `4-8h` / `<4h`）阶梯扣除违约金并办理退款 |
| `POST /api/orders/:id/dispatch` | 后台调度派单 | 平台管理员或 B端机构主管将订单指派/改派给匹配的陪诊师 |
| `POST /api/orders/:id/step` | 陪诊师 5步打卡 | 推进第 1~5 步履约状态；第 4 步自动生成《结果分享报告》《医嘱打卡》《复检提醒》《理赔资料包》；第 5 步自动结算分账 |
| `POST /api/medications/:id/toggle` | 医嘱执行(+) | 切换患者今日服药打卡完成状态 |
| `POST /api/diaries` | 健康日记与定时关怀(+) | 新增患者每日血压、血糖与平安关怀打卡记录 |
| `POST /api/commercial/:id/click` | 体检/购药/保险(+) | 记录合作平台入口有效导流点击并实时累加广告分成收入 |
| `POST /api/applications` | 供给端招募 | 提交 B端合作机构或个人持证陪诊师入驻申请 |
| `POST /api/applications/:id/approve` | 后台准入审批 | 审核通过入驻申请，自动将其加入活跃机构库或陪诊师运力池 |

## 七、 本地快速启动与自动化测试

### 1. 环境要求
- **Node.js**：`>= 22.5.0`（使用 Node.js 内置原生 `node:sqlite` 与 `node:http`，零外部依赖，开箱即用）。

### 2. 启动全栈服务
```bash
cd /Users/SEI/.gemini/antigravity/scratch/everwell-peizhen
npm start
```
启动成功后，五大商业交付模块均可独立访问并共享同一 SQLite WAL 实时数据库：
